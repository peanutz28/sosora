FROM GENERAL IMAGE FEATURES TO ROAD FLOOD LABELS

What did the model learn?

We adapted a small image model to classify flood state along annotated roads. Compare the same validation image before and after training, then check where the improvement stops.

1 · Start with image features

SegFormer-B0 already learned scene features on ADE20K. We kept those weights and replaced its classifier with a new, random two-class head: flooded road or non-flooded road.

2 · Learn from labeled examples

SpaceNet 8 · Louisiana / Ida 2021. Eight training tiles supplied 53 native 256px crops. A loss measures prediction errors against those labels; the optimizer adjusts weights to reduce that loss. All 3,714,658 parameters were trainable, including the encoder—not just the 514 classifier parameters.

3 · Select using validation

Two separate tiles supplied 11 validation crops. Ten CPU epochs ran with batch 4, AdamW and learning rate 0.00005. Epoch 9 was restored for the best crop-validation F1. No Germany labels selected it.

Does improvement extend beyond this image?

Both Louisiana validation tiles · development result

Same 35,313 labeled road pixels for every model/control. This set helped model development; it is not an independent test. Crop-validation F1 (.6142) uses different support and is not this full-tile score.

Frozen Germany check · six new tiles, two with flooded labels

The checkpoint and binary 0.5 decision were frozen before new label access. Same 72,961 labeled road pixels, native 256px windows and stride for every model/control. This small cross-event sample is not the official SpaceNet test or a deployment estimate.

Failure 1 · false alarms on a dry tile

All 2,417 false-positive pixels came from tile …_0_18_66. Aggregate improvement does not mean every image improved.

Failure 2 · a flooded tile was missed

Tile …_0_38_62 had 726 flooded labeled pixels; the tuned model missed all 726. The other positive tile reached F1 .8496.

Germany images are not displayed here and were not used for new tuning. No further training occurred to build this view. The initialization control shows learning relative to a random binary head, not superiority to an established flood model.

What this experiment cannot tell us

Four earlier Louisiana test tiles were reused after their images/results informed diagnosis. Their F1 .1858 → .6742 is not a pristine holdout claim. The crops overlap, the geographic sample is tiny, and only one seed was run. Buffered centerlines and residual image alignment can distort labels; off-road false alarms are not scored.

Helene imagery has no flood ground truth here. Its overlays are unverified transfer predictions. This experiment does not establish official closures, passability, current conditions or safe rescue routes. Nemotron report parsing is a separate integration; it was not fine-tuned in this experiment.

Exact checkpoint, training settings and reproduction

Base nvidia/segformer-b0-finetuned-ade-512-512, revision 489d5cd81a0b59fab9b7ea758d3548ebe99677da. Seed 42; CPU 2 threads; batch 4; unweighted cross-entropy ignoring 255; AdamW weight decay .01; no augmentation or learning-rate schedule. Ten epochs = 140 optimizer steps; selected epoch 9 = 126 steps. Best validation weights restored.

A separate frozen-encoder preset reached crop-validation F1 .4830; full adaptation reached .6142. Learning rate and epoch count also differed, so this does not isolate the effect of unfreezing.

Regenerate privately from existing local images/checkpoints: ml/.venv312/bin/python -m scripts.ml.build_finetuning_demo. It performs inference only, checks checkpoint hashes, and requires exact agreement with saved validation confusion counts. Generated image assets and weights stay outside Git.
